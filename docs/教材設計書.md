# 技術教材設計書 — Git / Docker / pytest / MLflow

## 1. 目的・対象者

機械学習開発を進める際に必要な「コード管理・環境管理・品質管理・実験管理」の主要ツールを、モデル開発の具体例を通じて理解し、基本操作を説明・実践できるようにする。対象はPythonと機械学習の基本を学んだ初学者。実際のツール操作を行う前の自習教材としても利用できるようにする。

## 2. 学習到達目標

- **Git**：変更履歴・ブランチ・復元・GitHubとの関係を説明し、必要な基本コマンドを選べる。
- **Docker**：Dockerfile・イメージ・コンテナ・volume・Composeの関係を説明できる。
- **pytest**：テストケース・assert・parametrize・fixtureを理解し、正常系／異常系の検証を設計できる。
- **MLflow**：Experiment/Run/Metric/Artifactを使った管理、SQLite/Artifact Store、Gitとの紐づけを説明できる。

## 3. 全体カリキュラム

順番はGit→Docker→pytest→MLflow。コードの追跡 → 実行環境 → 動作検証 → 実験結果とモデルの保存という機械学習開発の関係を意識して構成する。各講座は独立して選択可能にする。

## 4. 講座共通設計

1. 概要と導入
2. 基本概念
3. 仕組みと内部構造
4. 基本操作とコード例
5. 実践・ユースケース
6. 学習内容のまとめ
7. 理解度テスト（最後に10問）

教材は**ページ送り式**。受講中の各ページで図解・コード例・補足を組み合わせ、教材内容全体を1画面に長大なスクロール領域として置かない。講座内で必要な部分に限って疑似操作を挿入し、実際のシステムを動かす演習と区別する。

## 5. 理解度評価

各講座の最後に全10問の選択式テストを設置。未回答があれば採点しない。採点後に正誤・解説・スコアを表示し、再挑戦を許可する。7割以上を合格目安とし、その場合、講座最終ページを修了扱いとする。最高得点と受験履歴はブラウザに保持する。

## 6. Webアプリ設計

- 静的サイト：GitHub Pages / HTML / CSS / JavaScript ES Modules
- UI：Neural Daylightの明るい配色、レスポンシブ対応、中央の入口カード、学習ダッシュボード
- 遷移：ハッシュルーターによるクライアント側ページ切り替え
- 保存：IndexedDB（既存のデモDBを壊さず、新規キーに独立保存）
- 疑似演習：Git・Docker・pytest・MLflowの一部操作をJavaScriptで再現。**実際の外部コマンドは実行しない**。
- 進捗：明示的な「学習済みにして次へ」で完了記録、最後のテストは採点によって判定
- 出力：進捗・採点履歴・疑似操作履歴のJSONダウンロード

## 7. 品質確認と制約

全講座に対しページIDの重複、最終ページがテストであること、問題の正答範囲、各ページの教材構成、講座ごとの疑似演習が存在することをNode.jsで検証する。ブラウザ内保存はユーザー認証や端末間同期を提供しない。図解・疑似演習は概念理解を目的とし、実ツールの代用とはしない。
