# 技術教材設計書 — Git / Docker / pytest / MLflow

## 1. 目的と対象

機械学習開発に必要なコード・実行環境・品質・実験の管理方法を、Pythonと機械学習の基礎を理解している初学者に伝える。用語だけでなく、目的、データの保存場所、内部での変化、コマンドの結果、活用場面を説明できることを目指す。

## 2. 全講座共通の8段階

| 順番 | セクション | 必要な内容 |
|---|---|---|
| ① | **達成目標** | 修了後に理解・実行できること |
| ② | **目的（なぜ学ぶのか）** | 解決したい問題・現場で必要な理由 |
| ③ | **概念（イメージ図）** | 全体像・主な要素とその関係 |
| ④ | **仕組み・構造** | 内部の保存・参照・処理の順序 |
| ⑤ | **基本操作** | コマンド、引数、出力と実行前後の状態 |
| ⑥ | **ユースケース** | DemandPilotのような機械学習開発の一連の実例 |
| ⑦ | **まとめ** | 知識・処理の関連付けと現場の確認事項 |
| ⑧ | **知識問題** | 最後にまとめて理解を確認、正誤理由を提示 |

## 3. 原稿制作の方針

- 説明量・ページ数には制限を設けない。初出用語は必ず説明する。
- 図解はその要素の役割と矢印の意味を本文でも説明する。
- コマンドは「いつ使うか」「何が変化するか」「出力で何を確認するか」を示す。
- ブラウザ内疑似操作は実環境の操作とは異なることを明記する。
- 途中にテスト問題を散らさず、全講座の最後にまとめる。
- データ漏えい、未コミット変更の喪失、誤ったGit操作などの危険を具体的に説明する。

## 5. Webアプリの前提

GitHub Pagesから公開するHTML/CSS/JavaScript ES Modulesによる静的アプリ。IndexedDBに端末別の学習記録を保存し、認証・ユーザー間同期は行わない。教材原稿は画面処理とは分離する。

## 6. 検証

各講座のページID・設問構造、Gitの8段階順序、最後に知識問題が配置されること、シミュレーションとの整合性をNode.jsで確認する。コマンド例は実行対象により挙動が異なる場合があるため、単なる出力例と実行可能なコマンドを明確に区別する。
