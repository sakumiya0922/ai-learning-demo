# 技術教材設計書 — Git / Docker / pytest / MLflow

## 1. 目的と対象

機械学習開発に必要なコード・実行環境・品質・実験の管理方法を、Pythonと機械学習の基礎を理解している初学者に伝える。用語だけでなく、目的、データの保存場所、内部での変化、コマンドの結果、活用場面を説明できることを目指す。

## 2. 全講座共通の8段階

| 順番 | セクション | 必要な内容 |
|---|---|---|
| ① | **達成目標** | 修了後に理解・実行できること |
| ② | **目的（なぜ学ぶのか）** | 解決したい問題・現場で必要な理由 |
| ③ | **概念（イメージ図）** | 全体像・主な要素とその関係 |
| ④ | **仕組み・構造** | 内部の保存・参照・処理の順序 |
| ⑤ | **基本操作** | コマンド、引数、出力と実行前後の状態 |
| ⑥ | **ユースケース** | DemandPilotのような機械学習開発の一連の実例 |
| ⑦ | **まとめ** | 知識・処理の関連付けと現場の確認事項 |
| ⑧ | **知識問題** | 最後にまとめて理解を確認、正誤理由を提示 |

## 3. 原稿制作の方針

- 説明量・ページ数には制限を設けない。初出用語は必ず説明する。
- 図解はその要素の役割と矢印の意味を本文でも説明する。
- コマンドは「いつ使うか」「何が変化するか」「出力で何を確認するか」を示す。
- ブラウザ内疑似操作は実環境の操作とは異なることを明記する。
- 途中にテスト問題を散らさず、全講座の最後にまとめる。
- データ漏えい、未コミット変更の喪失、誤ったGit操作などの危険を具体的に説明する。

## 5. Webアプリの前提

GitHub Pagesから公開するHTML/CSS/JavaScript ES Modulesによる静的アプリ。IndexedDBに端末別の学習記録を保存し、認証・ユーザー間同期は行わない。教材原稿は画面処理とは分離する。

## 6. 検証

各講座のページID・設問構造、全講座の8段階順序、最後に知識問題が配置されること、シミュレーションとの整合性をNode.jsで確認する。コマンド例は実行対象により挙動が異なる場合があるため、単なる出力例と実行可能なコマンドを明確に区別する。


## 7. Web教材の画面構成（v3）

- 目次は8章の見出しで折りたたみ、現在の章のみ初期展開する。
- 目次と教材を画面高さに収め、別々にスクロールさせる。ページ全体はスクロールさせない。
- 各ページの到達目標欄は廃止し、冒頭の達成目標ページと8章の学習マップに集約する。
- 教材本文の下に独立したナビゲーションバーを設け、ページ移動ボタンを常に表示する。
- 本文では関係図、分岐図、ファイル構成図、時間軸、操作前後の比較図を内容に応じて使い分ける。
- モバイルでは章別目次を折りたたみメニューに切り替える。
- 元の学習履歴は残す。Git講座の既存ページIDは維持し、他の3講座は導入ページだけ追加する。
- ブラウザ内の疑似操作はGitやMLflowなどの実行を保証しない旨を演習箇所で明示する。

## 8. 教材画面の読み進め方（v4）

- 各ページの最初に、**最重要の結論を1つ**配置する。教材本文は、その結論を理解するための根拠・図・操作に限定する。
- 説明文は**言い切りの常体**に統一する。ソースコード自体の文言・構文は変更しない。
- 結論の直後に図解を優先配置する。続く解説・比較表・操作例・注意点は「PART 01」「PART 02」…で区切る。
- 左右フレームは別々にスクロールさせ、**「前のページへ」「次のページへ」**ボタンをフレーム外の左右端に固定する。ボタンを囲う余分な枠は置かない。
- **キーボード←/→**でもページを移動する。入力欄・クイズ選択肢などのキー操作を優先し、最終ページより先には移動しない。
- 最後のページは知識問題。採点はページ内で行い、ページ移動用の名称を採点や講座終了に流用しない。
- **画面と教材データを分離**し、`courses/keypoints.js` が1ページ1メッセージの結論、`courses/editorial.js` が説明文の常体表示を担う。

Git講座の元原稿は39項目。v5では説明のまとまりを最大3パートに整理し、続きのページを追加して42ページとする。元のページIDは維持し、新しい続きページのみIDを追加する。

## 9. パートと文章の整理（v5）

- 全ページは「結論 → PART番号と内容名 → 図・表・コード・説明」という順序。
- PARTの分類名・色分けした左枠・VISUAL GUIDEの表示を削除。
- 1パートはブロック種別ではなく、説明の意味のまとまり。ノートは前のパートへ統合。
- 1ページ最大3パート。超過分は同じ章の続きページに分割し、既存ページのIDは保持。
- 本文の「です・ます」を常体に揃え、機械的な誤活用を検出して修正。
- 画面内容と学習状態の保存先・問題の採点処理は変更しない。


## 11. 操作体験と表示の整理（v6）

見出しは小さな四角とタイトルに統一。PART表記、パート番号、補助分類ラベルは表示しない。章番号は目次と現在位置にのみ使用する。

教材本文は1ページ最大3セクションを維持。結論→操作・図解→詳しい説明という順序を保ち、情報の削除によってページを短くしない。図解や既存演習に対応するデモだけを置き換え、本文・コード例・注意事項を保持する。

背景、外枠、文字サイズ、余白を単一のスタイルシートで定義。装飾用のグラデーション、重なるカード、意味を持たない縦線を取り除く。操作中の変更は枠色だけでなく状態名と数値で示す。

12種類の操作デモを48ページに配置。Gitは37ページ、Dockerは3ページ、pytestは3ページ、MLflowは5ページ。教材のページ数はGit42・Docker13・pytest13・MLflow13の計81ページ。ページID・採点問題・保存キーは維持。

デモの状態は`demos`にページ単位で保持し、JSON出力にも含める。既存の`completed`、`quizAttempts`、`labs`、アーカイブ履歴は維持。左右キーはデモ内の操作要素や入力欄を優先し、それ以外で前後ページへ移動する。

詳細な状態モデルと参照資料は`操作デモ.md`を参照。
