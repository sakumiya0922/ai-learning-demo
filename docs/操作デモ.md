# 操作デモ

Gitの37ページ、Docker・pytest・MLflowの11ページに、合計12種類のブラウザ内操作デモを配置。

## 構成

| ファイル | 役割 |
|---|---|
| `courses/demo-map.js` | 教材ページと操作デモの対応 |
| `app/demo-state.js` | 副作用のない状態遷移 |
| `app/demo-view.js` | 状態の表示と操作ボタン |
| `tests/demos.test.js` | 状態遷移のテスト |
| `tests/demo-git.test.js` | 隔離した一時フォルダでの実Gitとの照合 |

## 操作対象

リポジトリの初期化、ステージング、ローカルとリモート、ブランチ、コンフリクト、過去版の参照・復元、Gitオブジェクト、保存場所、除外設定、実験記録、コンテナと永続化、テスト結果。

## 原則

実際のGit・Docker・Pythonコマンドはブラウザから実行しない。コミットID、実験数値、モデル保存先は教材用。既存の教材本文とページIDを維持し、該当する図・演習を操作デモに置き換える。

操作デモはページごとに状態を保持。学習進捗とは独立し、デモのリセットは他ページや採点結果に影響しない。

ステージングのモデルは、作業ファイル・index・HEADを独立した値として保持する。add後の再編集はindexに反映しない。commit後もindexは保存済み内容を保持する。

リモートのモデルは、自分のmain・origin/main・GitHub側mainを独立した参照として保持する。fetchはorigin/mainのみ更新。pull --ff-onlyは履歴が分岐した場合に統合を停止する。pushでリモートの変更を上書きしない。

コンテナのモデルは、停止と削除を区別する。停止では内部データを維持し、削除ではコンテナ内だけのデータを失う。バインドマウント先のデータは別に保持する。

## 範囲と制約

実Gitのすべてのオプション、フック、競合ケース、権限、ファイルシステムを再現するものではない。ブランチ操作は未コミット変更のない状態、復元は練習用1ファイルを対象とする。疑似Runのモデル本体は生成しない。操作の目的と状態変化を比較するための教材。
